# Benchmarking & Evaluation Report

## Current deterministic replay

The repository replay currently reports:

| Gate | Deterministic replay result | Target | Interpretation |
|---|---:|---:|---|
| G2 Early Retrieval | 100% | >= 80% | Control-flow suite passes |
| G3 Multi-Intent | 100% | >= 70% | Decomposition suite passes |
| G4 Grounding/Citation structure | Pass | >= 85% support | Provenance/grounding structural check passes |
| G5 Session refinement | Pass | Verified continuity | Delta retrieval preserves prior session state |
| G6 Trace schema | Implemented | 100% trace coverage | Every `/chat` turn records a trace event |

These numbers are from deterministic replay doubles, not from the private/held-out
corpus or a live Gemini model. They must not be presented as final model-quality
benchmark results.

## Edge cases covered

1. Incomplete transcript fragment -> `WAIT`.
2. Presentation-only request with an existing answer -> `NO_RETRIEVAL`.
3. Late detail expressed as a statement -> targeted delta retrieval.
4. Incremental compound request -> full accumulated multi-intent decomposition.
5. Duplicate retrieval -> suppression within a session.
6. Citation support -> only retrieved chunk IDs are eligible.

## Ablations

`scripts/run_ablations.py` contains two runnable architecture measurements:

1. Dense-only retrieval vs hybrid retrieval.
2. Production retrieval controller vs a simple baseline controller can be
   measured by extending the replay harness.

The current script uses deterministic doubles so it can run without external
providers. Final reported values should be generated by replaying the held-out
corpus with the same query set and recording retrieval recall, groundedness,
citation support, latency, and token/cost metrics.

## Edge-case failure analysis

The following failure modes are explicitly exercised and documented because they
are easy to regress while optimizing latency:

1. **Premature retrieval on an incomplete fragment.** A fragment such as `I need to`
   must remain `WAIT`; retrieving here increases false-trigger rate and wastes
   retrieval work. The controller therefore requires stability/context signals.
2. **Late detail causing a full restart.** A new constraint after an existing answer
   must retrieve only the delta and preserve the prior answer state/citations. A
   regression that clears session state would violate G5 and increase latency/cost.
3. **Unsupported citation/provenance.** A generated statement must not acquire a
   citation ID that was not present in retrieved evidence. The citation manager
   derives IDs exclusively from retrieved chunks, while grounding exposes unsupported
   sentences as uncertainty instead of silently treating them as factual.

These are failure-mode analyses, not claims that the current implementation fails
these cases. The deterministic regression suite is expected to keep them passing.
